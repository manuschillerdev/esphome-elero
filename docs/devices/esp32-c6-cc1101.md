# ESP32-C6 + CC1101

ESP32-C6 dev board (ESP32-C6-DevKitC-1, ESP32-C6-WROOM-1) with a CC1101 868 MHz
RF module connected over SPI.

The C6 is a RISC-V part, so its GPIO map and strapping pins differ from the
Xtensa ESP32. The wiring below is the generic ESP32 wiring with the chip select
moved off a strapping pin.

## Wiring

| CC1101 | ESP32-C6 | Function |
|--------|----------|----------|
| VCC | 3V3 | Power (3.3V only!) |
| GND | GND | Ground |
| SCK | GPIO18 | SPI clock |
| MOSI | GPIO23 | SPI data out |
| MISO | GPIO19 | SPI data in |
| CSN | GPIO6 | SPI chip select |
| GDO0 | GPIO3 | Interrupt pin |

GDO2 is not used. SPI pins are configurable -- any valid GPIO works.

> **WARNING:** The CC1101 operates at **3.3V**. Never connect it to 5V!

### Strapping pins

**GPIO5 is a strapping pin on the ESP32-C6** and must not be used for chip
select, which is why this wiring uses GPIO6. The generic ESP32 config in
[esp32-cc1101.md](esp32-cc1101.md) puts CSN on GPIO5 -- do not copy that pin
onto a C6.

Pins to avoid on the ESP32-C6:

| GPIO | Function | ESPHome behaviour |
|------|----------|-------------------|
| 4, 5 | Strapping -- JTAG signal source select | Warns |
| 8, 9 | Strapping -- boot mode (GPIO9 is the BOOT button) | Warns |
| 15 | Strapping -- ROM message printing | Warns |
| 12, 13 | USB Serial/JTAG data lines | Warns |
| 24-30 | SPI flash / PSRAM | Rejected |

Attaching a CC1101 to a strapping pin can leave the board unable to boot.
Valid GPIO numbers on the C6 are 0-30.

## ESPHome Config

The C6 requires the **ESP-IDF** framework. There is no Arduino core for it in
ESPHome.

```yaml
esp32:
  board: esp32-c6-devkitc-1
  framework:
    type: esp-idf

spi:
  clk_pin: GPIO18
  mosi_pin: GPIO23
  miso_pin: GPIO19

elero:
  cs_pin: GPIO6
  gdo0_pin: GPIO3
```

## Frequency

The default register preset works with the Elero motors tested on this board.
If discovery finds nothing, try the alternative preset:

| Preset | freq2 | freq1 | freq0 | Carrier |
|---|---|---|---|---|
| Standard (default) | `0x21` | `0x71` | `0x7a` | 869.525 MHz |
| Alternative | `0x21` | `0x71` | `0xc0` | 869.553 MHz |

Carrier values are computed from the CC1101 `FREQ2`/`FREQ1`/`FREQ0` registers
with the module's 26 MHz crystal.

```yaml
elero:
  cs_pin: GPIO6
  gdo0_pin: GPIO3
  freq0: 0xc0    # alternative preset
  freq1: 0x71
  freq2: 0x21
```

## Verifying the radio

With `logger.level: DEBUG`, a working CC1101 reports `MARCSTATE=0x0d` (RX) after
setup, and received Elero frames are logged with `crc_ok: true`.

## Known issues

Log lines that print `uint32_t` values with `%u` or `%x` are garbled on the C6.
`uint32_t` is `long unsigned int` on RISC-V, so those format specifiers do not
match. This is cosmetic -- it affects log output only, not RF behaviour.
